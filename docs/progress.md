# Progress log

A plain-language diary of the WTA Finals simulator, one entry per milestone.

## Milestone 1 — Bend runs in the cloud (2026-10-03)

**What works now:** Bend 2 (version 2.0.35) installs in a few seconds in the
Claude Code cloud machine, and a hello-world both runs and compiles to a native
program. The project folders are in place, waiting for code.

**Interesting finding:** Bend really does spread work across every core with no
extra effort. A toy program that makes 268 million tiny function calls took
1.41 seconds on one core and 0.37 seconds on all four — almost exactly 4× faster.

**Also:** I tried to "prove" that double(2) equals 5. Bend refused, saying it
expected 4. That refusal is the whole point of the project: tennis scoring rules
will be checked the same way.

**Machine:** 4 CPU cores (Intel Xeon, 2.1 GHz), 15 GB memory, no GPU.

## Milestone 2 — the game layer, proven (2026-10-03)

**What works now:** the engine can score a tennis game: who has won, and what
happens after each point, deuces and advantages included. Nine laws describe
the rules, and Bend has checked a proof of every one, so they hold for every
possible score, not just the ones a test happens to try. That includes deuce
after 3 points each, after 30, or after a million.

**Interesting finding:** I planted five realistic bugs in the scoring code, one
at a time. Bend rejected every one and named the law it broke:

| Planted bug | Caught by |
| --- | --- |
| Game won with a 1-point lead | L2 (game rule) |
| Game won with only 3 points | L2 (game rule) |
| Point given to the wrong player | L20 (each point goes to its winner) |
| Points still counted after the game ended | L5 (a won game is final) |
| Player B's win reported as player A's | L2 (game rule) |

The third one is the best part. That bug would have slipped past the four
laws in the original plan, because they only check who has won and that a
finished game stays finished. Reviewing the laws before writing any code
exposed the gap, and the new law (L20) was added before the code existed.

## Milestone 3 — tiebreaks, sets and matches, proven (2026-10-03)

**What works now:** the engine plays whole matches: tiebreaks (including the
10-point kind), sets, best-of-three matches, and who serves every point. 28
new laws (37 in all, plus 20 worked examples) describe the rules, and Bend
has checked a proof of every one. Some
are about every way a set or match can possibly go: "every set played from
0-0 ends 6-0 to 6-4, 7-5 or 7-6" holds for every possible sequence of points,
not just the ones a test tried.

**Interesting finding:** I planted nine realistic bugs, one at a time. Bend
rejected every one:

| Planted bug | Caught |
| --- | --- |
| Tiebreak won with a 1-point lead | yes |
| First tiebreak server serves two points instead of one | yes |
| Set won 6-5 | yes |
| No tiebreak at 6-6 (games just carry on) | yes |
| Deciding-set tiebreak uses the wrong target | yes |
| Serve order restarts every set | yes |
| A set credited to the player who lost it | yes |
| Finished set not recorded | yes |
| Points still played after the match is over | yes |

The serve-order bug is the kind the spec warned about: the results would
still look like tennis, and no one would notice by watching the numbers.

**A number:** the full proof (about 3,900 lines, part of it generated by a
script that checks every small score) is checked in 0.3 seconds.
